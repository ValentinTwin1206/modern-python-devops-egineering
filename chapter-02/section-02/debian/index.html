    Debian Packages¶

    Debian packages distribute applications as .deb archives that APT can discover, verify, install, upgrade, and remove. This guide applies the OS package fundamentals to the simply-journal-admin Debian package.

    Applied Project¶

    Project Setup¶

    The applied project is a small cross-platform admin CLI called simply_journal_admin, exposed as the simply-journal-admin command. It reads recent log entries from the host operating system through a unified interface while using platform-specific packaging: a Debian package for Linux and an MSI package for Windows. On Linux it imports systemd.journal from the APT package python3-systemd; on Windows it reads the Event Log through pywin32 with a wevtutil fallback. This makes it a good fit for operating-system packaging because installation, service integration, and runtime dependencies are intentionally managed at the operating-system level.

    Run the Project¶

    Application, test, lint, packaging, and shell-exit commands are documented in the section README.

    Building Blocks¶

    Debian packages are AR-based .deb artifacts used by Debian, Ubuntu, and related Linux distributions. A package combines an installable filesystem payload with metadata that describes its identity, architecture, dependencies, and lifecycle scripts. Debian packages are typically used for system utilities, services, command-line applications, and software that depends on libraries managed by the operating system.

    The Debian packaging workflow connects four building blocks: the .deb artifact stores the payload and generated metadata, maintainer files under debian/ define how the package is built, APT and dpkg install and track it, and an APT repository publishes package files together with signed indexes.

    Building Block Role Debian Example
    Package Format Stores the installable filesystem payload and generated control metadata. .deb
    Maintainer / Metadata File Defines package identity, dependencies, build rules, installed paths, and release history. debian/control, debian/rules, debian/changelog, debian/{package-name}.install
    Package Manager Resolves repository dependencies, downloads packages, installs files, and records package state. apt, dpkg
    Remote Repository Publishes .deb artifacts and signed indexes that APT downloads and verifies. Debian or Ubuntu repositories, Cloudsmith

    Project Layout¶

    The Debian packaging layout centers on the maintainer files under debian/:

    {project_root}/
└── debian/
    ├── changelog
    ├── control
    ├── postinst
    ├── rules
    ├── {package-name}.install
    └── source/
        └── format
    • changelog: Records package versions, distribution targets, urgency, and release notes. Debian tools also use its latest entry to determine the package version.
    • control: Defines source and binary package metadata, build requirements, runtime dependencies, architecture, and the package description.
    • postinst: Runs package-maintainer logic after installation finishes, such as refreshing caches or registering integration points.
    • rules: Provides the executable build entry point that dpkg-buildpackage invokes, commonly through Debhelper.
    • {package-name}.install: Maps built files into their destination paths in the binary package.
    • source/format: Selects the Debian source package format, such as 3.0 (native) or 3.0 (quilt).

    Package Manifest¶

    The Debian control file defines the package identity, build requirements, runtime dependencies, and end-user package description.

    Source: simply-journal-admin
Section: admin
Priority: optional
Maintainer: Modern Python Engineering
Build-Depends: debhelper-compat (= 13)
Standards-Version: 4.7.0
Rules-Requires-Root: no
Homepage: https://github.com/ValentinTwin1206/modern-python-devops-egineering

Package: simply-journal-admin
Architecture: any
Depends:
 ${misc:Depends},
 ${shlibs:Depends},
 python3-systemd
# Recommends: <recommended-runtime-package>
# Suggests: <optional-runtime-package>
Description: cross-platform admin CLI for reading systemd journal entries
 simply-journal-admin is a command-line tool that reads recent systemd journal
 entries (Linux) through the APT-managed python3-systemd binding. The same code
 base also supports the Windows Event Log when installed from the MSI package.
 .
 The Debian package ships a fully offline runtime under
 /opt/simply-journal-admin: an embedded Python interpreter, the unpacked
 project wheel, and a thin wrapper at /usr/bin/simply-journal-admin. No pip,
 virtualenv creation, or internet access is needed on the target host.
    • Source: Declares the source package name used by Debian packaging tools.
    • Build-Depends: Lists the tools required to build the .deb package.
    • Package: Names the binary package that end users install.
    • Architecture: Declares the target architecture or marks the package as architecture-independent.
    • Depends: Lists required runtime packages alongside dependency substitutions generated by Debhelper. For example, OS-level packages such as python3-systemd belong here, so APT installs them automatically and the user does not need to install them separately with uv or pip.
    • Description: Provides the short summary and indented long description shown by package-management tools.

    Package Layout¶

    A Debian package is an AR archive. Inside that archive, Debian stores a small format marker, a metadata archive, and a payload archive. The metadata archive describes what the package is, which dependencies it needs, and which maintainer scripts package tools may run during install, upgrade, or removal. The payload archive contains the files that are unpacked onto the target system.

    {package-name}_{version}_{arch}.deb
├── debian-binary
├── control.tar.xz
│   ├── control
│   ├── md5sums
│   ├── postinst
│   └── ...
└── data.tar.xz
    ├── usr/
    │   └── share/
    │           └── ...
    ├── etc/
    │   └── {package-name}/
    │       └── ...
    └── opt/
        └── {package-name}/
            └── ...
    • debian-binary: Records the Debian package format version.
    • control.tar.*: Bundles package metadata and maintainer files such as postinst or prerm that dpkg may execute while APT installs, upgrades, or removes the package.
    • data.tar.*: Bundles the filesystem payload that is deployed onto the machine.

    The exact contents of data.tar.* depend on the package. A command-line tool might install a launcher under /usr/bin, shared assets under /usr/share, configuration defaults under /etc, or an application payload under /opt. Runtime packages declared in Depends, such as python3-systemd, are resolved by APT during installation instead of by uv or pip.

    Packaging Workflow¶

    Info

    This workflow assumes that you have a valid Cloudsmith repository and API key. Replace <cloudsmith-repo> with your Cloudsmith repository slug, export CLOUDSMITH_API_KEY on the host, and pass both values into the container.

    Create the OS Package¶

    Use the helper script to open the Linux packaging environment.

    ../build.sh build --path proj2_journal_admin/Dockerfile.devEnv \
    --cloudsmith-workspace "<cloudsmith-repo>" \
    --cloudsmith-api-key "$CLOUDSMITH_API_KEY"

    Inside the container, synchronize the environment and build the wheel:

    uv sync --all-groups

    Build the wheel artifact into the shared build directory:

    uv build --wheel --out-dir /build

    Run the Debian package build to create the .deb artifact. Use the build-deb.sh script so that the build does not pollute the container or host environment:

    ./scripts/build-deb.sh

    The resulting .deb package is written to the .build output directory on the host.

    Inspect the Package¶

    A Debian package (.deb) is an AR archive that contains debian-binary, a compressed control.tar.* metadata archive, and a compressed data.tar.* payload archive.

    List the AR members inside the Debian package.

    ar t /build/simply-journal-admin_2.0.0-1_amd64.deb

    Inspect the Debian control metadata, including package name, version, architecture, dependencies, and description.

    dpkg -I /build/simply-journal-admin_2.0.0-1_amd64.deb

    List the filesystem payload that the Debian package installs.

    dpkg -c /build/simply-journal-admin_2.0.0-1_amd64.deb

    Publish the OS Package¶

    Debian repositories are typically managed using repository software such as Cloudsmith rather than directly by package maintainers. The package maintainer creates the .deb, which contains the package metadata from the Debian control file. Cloudsmith stores the artifact, extracts that metadata, and generates the repository metadata that APT consumes. APT reads the generated repository metadata first and uses it to locate the correct .deb file.

    The directory tree below illustrates the generic structure of a Debian-compatible APT repository. The placeholders represent values resolved when a package is published.

    /
├── dists/
│   └── {suite}/
│       ├── InRelease
│       ├── Release
│       ├── Release.gpg
│       └── {component}/
│           └── binary-{arch}/
│               └── Packages.gz
└── pool/
    └── {component}/
        └── {package-prefix}/
            └── {package-name}/
                └── {package-name}_{version}_{arch}.deb
    • / – The repository root configured in the APT source. It serves as the entry point for all repository metadata and package downloads.
    • dists/{suite}/ – Stores repository metadata for a Linux distribution. For example, {suite} becomes noble for Ubuntu 24.04. Cloudsmith generates files such as InRelease, Release, Release.gpg, and the package indexes that APT consumes.
    • dists/{suite}/{component}/binary-{arch}/ – Stores package indexes such as Packages.gz. They contain metadata extracted from uploaded packages, including package name, version, architecture, dependencies, checksums, and artifact location.
    • Packages.gz – The compressed package index that APT downloads during apt update. Cloudsmith regenerates it whenever publication changes the packages available for that target.
    • Release – Summarizes one suite and records checksums for its package indexes.
    • Release.gpg – Provides the detached GPG signature that APT uses to verify the Release file.
    • pool/{component}/... – Stores the uploaded .deb artifacts. During apt install, APT locates an artifact through Packages.gz, downloads it, and hands it to dpkg.

    From the projects/ directory, open the dedicated Debian packaging container and forward the Cloudsmith configuration into the container session.

    ../build.sh build --path proj2_journal_admin/Dockerfile.devEnv \
    --cloudsmith-workspace "<cloudsmith-repo>" \
    --cloudsmith-api-key "$CLOUDSMITH_API_KEY"

    You can upload the same .deb package into multiple Ubuntu distributions because Cloudsmith generates repository metadata independently for each target distribution. The noble and resolute segments tell Cloudsmith which distribution-specific metadata to generate.

    cloudsmith push deb "${CLOUDSMITH_REPOSITORY}/ubuntu/noble" \
    .build/simply-journal-admin_2.0.0-1_amd64.deb

    noble targets Ubuntu 24.04.

    cloudsmith push deb "${CLOUDSMITH_REPOSITORY}/ubuntu/resolute" \
    .build/simply-journal-admin_2.0.0-1_amd64.deb

    resolute targets Ubuntu 26.04.

    Verify that Cloudsmith indexed the uploaded package.

    cloudsmith list packages "${CLOUDSMITH_REPOSITORY}" -q "simply-journal-admin"

    APT clients can now download the repository metadata during apt update, discover simply-journal-admin, and install it normally.

    Consumer Workflow¶

    Configure the Package Manager¶

    Before installing a package from a private Debian repository, configure APT on the target machine. APT needs a trusted signing key, a source file that points to the repository, and a refreshed local package index before it can resolve and install a Debian package.

    Import the signing key from your Cloudsmith repository. APT uses this key to verify repository metadata before trusting packages from the repository.

    curl -fsSL "https://dl.cloudsmith.io/public/<cloudsmith-repo>/gpg.key" | sudo gpg --dearmor -o /usr/share/keyrings/cloudsmith-repository.gpg

    Add the Debian repository to the local APT sources by creating a deb822 source file.

    printf 'Types: deb\nURIs: https://dl.cloudsmith.io/public/<cloudsmith-repo>/deb/ubuntu\nSuites: noble\nComponents: main\nSigned-By: /usr/share/keyrings/cloudsmith-repository.gpg\n' | sudo tee /etc/apt/sources.list.d/cloudsmith.sources

    The dedicated source file cloudsmith.sources contains the repository metadata in stanza form.

    Types: deb
URIs: https://dl.cloudsmith.io/public/<cloudsmith-repo>/...
Suites: noble
Components: main
Signed-By: /usr/share/keyrings/cloudsmith-repository.gpg
    • Types: Tells APT which repository format to read. deb means this source provides binary packages for installation.
    • URIs: Declares the repository base URL that APT uses before resolving release-specific metadata and package indexes.
    • Suites: Selects the release subtree. Here, noble points APT to the Ubuntu 24.04 metadata.
    • Components: Selects the repository component. Here, main identifies the package index inside the noble release.
    • Signed-By: Restricts signature verification to the imported Cloudsmith keyring.

    Refresh the local APT metadata. APT verifies the release metadata with the key named by Signed-By, then selects the package index for the host architecture.

    sudo apt update

    For an amd64 host, the entries illustrated above produce this package-index URL based on specified entries for URIs, Suites, Components. 

    https://dl.cloudsmith.io/public/<cloudsmith-repo>/deb/ubuntu/dists/noble/main/binary-amd64/Packages.gz

    This follows the repository layout shown above. APT may negotiate another available compression format, such as Packages.xz, but the index contains the same package metadata.

    Inspect the downloaded package index in APT's local metadata cache.

    batcat /var/lib/apt/lists/*modern-python-engineering*_Packages

    The expected output should include these important fields:

    Package: simply-journal-admin
Version: 2.0.0-1
Architecture: amd64
Depends: libbz2-1.0, ..., python3-systemd
Description: cross-platform admin CLI for reading systemd journal entries
 simply-journal-admin is a command-line tool that reads recent systemd journal
 ...
Filename: pool/noble/main/s/si/simply-journal-admin_2.0.0-1/simply-journal-admin_2.0.0-1_amd64.deb
SHA256: <sha256>

    The Filename field gives APT the package path inside /pool. Combined with the repository base URL, it lets APT build the full download URL for a specific version.

    Install the OS Package¶

    Install the published package through APT. This command reads the cached repository metadata, resolves simply-journal-admin, downloads its .deb archives and dependencies, and invokes dpkg to unpack and register the package.

    sudo apt install simply-journal-admin

    Run the command to confirm that the launcher works and can read recent journal entries on the host.

    simply-journal-admin --since-minutes 60

    Ask dpkg which files it recorded for the package.

    dpkg -L simply-journal-admin
